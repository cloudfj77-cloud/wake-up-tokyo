# 需求与证据清单

本表是后续迁移的验收标准，不是本次实现声明。当前起点来自样板 0.1.0 的记录，执行时必须核对实况。每个阶段只验自己范围，未进入的阶段标记“未执行”，不要批量填写通过。

## 需求核对

| 项目 | 样板当前起点 | 后续验收要求 |
|---|---|---|
| 原生工程 | 已有 WebGPU／ECS 原生路线 | 运行实际后端可确认；没有以 Three.js／iframe 渲染代替 |
| 咖啡店场景 | 真实场景切片已导入 | 几何、贴图、透明材质、色彩、同机位表现逐项核对原版 |
| 人物贴图与动作 | 网格已导入，缺完整贴图／动画 | 可辨认原角色；真实移动、跳、滚、持枪、射击对应动作 |
| 移动与跳滚 | 状态和位移切换有基础实测 | 移动中一次空格滚；Shift 跳；交替切换、落地不会卡住 |
| 墙体与楼梯 | 只有简化地面高度 | 角色／相机／弹体的碰撞与遮挡；完整上楼进店再返回 |
| 命中蓄力 | 简化三次命中规则已实现 | 不命中不涨；三次有效命中后下一发强化；事件不重复计数 |
| 注射器 | 简单肩部几何 | 角色视角明确能看到武器和紫色液体，发射有可见回弹 |
| 拾取与引导 | 简单黄色标记和拾取 | 咖啡店原版位置、光圈／发光、提示、装备、刷新规则一致 |
| 喷汁与留痕 | 简单弹体和地面形状，最多 64 个 | 真实喷射感；地面／墙面；场景持续性和存档按原版核对 |
| 感染主标与侧边记录 | 简单成功标和计数 | 仅个人亲自感染弹主标；侧边同步；六尖累积循环与消退时长 |
| 感染音效 | 临时合成音 | 实际可听到原版主要爆炸反馈；手势解锁、音量、叠加不爆音 |
| 敌友和生命 | 代理对象红绿转换，玩家生命是简化显示 | 真实红敌绿友／绿玩家，稳定不透明；感染后行为和阵营一致 |
| 卡片与能力 | 未迁移 | 点卡立即获得；刷新只动目标卡；能力按获得顺序排列 |
| 列车、任务、警戒、Boss | 未迁移 | 两侧列车站内持续运动；完整任务/Boss 可正常触发和结束 |
| 完整地图、默认入口 | 只有咖啡店切片 | 原生完整海滨默认入口，东京可选，正常流程都能游玩 |
| 剧情、设置、存档、手机 | 未迁移 | 原版最新明确要求逐项还原，独立存档键空间，不损坏原存档 |
| 性能 | 历史局部静置窗口两边约 60 帧 | 配对负载、实际完成帧、长时间实测；不把已有结果外推整款 |

## 防止“测试通过，但体验没还原”

- 对照原游戏的只读源码／实机／已验收截图；不能只让新原生版与共用新规则的 reference 互相证明。
- 输入测试必须走真实输入采样和游戏逻辑，不直接改投影数值；投影只读，不能给测试暴露答案或摆放专用敌人。
- 动作测试既看状态，也看角色模型实际姿势与位移。截图不会证明动画衔接，应补真实组合动作记录。
- 感染既看计数，也看阵营、模型过渡、血条、主标、侧边记录和声音。画面证据不证明音效可听。
- 资产导入、类型检查、构建和 HTTP 状态是基础检查；正式验收来自最终代码的官方 owner 浏览器游玩。
- 保留阶段开始前已通过要求的回归；新实现不能把卡片、指针锁定或其他控制弄坏。

## 最终代码检查入口

运行前读取本机 CLI help 确认参数。当前项目基础入口：

```sh
pnpm exec forgeax project check --json
pnpm typecheck
pnpm test
pnpm exec forgeax asset verify --json
pnpm build
pnpm exec forgeax project play scripts/playthrough.mjs --backend hardware --headless true --require-ui --viewports 1280x720,1280x600 --timeout-ms 180000 --json
```

180000 是脚本超时示例，不代表整项任务预算；按本阶段实际行为调整，不盲目照抄。按项目要求运行官方验收，遵守宿主工具等待规则，不能因命令仍运行就声称通过。阶段有画面变动时查看实际生成 PNG；输入／场景与刷新必须验证。需要诊断再启用 RHI Debug，调试捕获不代替验收。

资产检查要看实际作用域、产出数量与遗漏项；空结果或未物化的 Pack 不算所有资源验证。构建后复核实际资源，并记录与官方游玩加载的对应关系。

## 证据保存

每次在 `docs/evidence/<阶段>-<日期>-<短提交或标识>/` 下保存本阶段证据与说明，保留旧结果。先写明被测提交；测试后再改代码则旧证据失效，标明最后改动并重测受影响项。文档目录只保存记录，不充当引擎资产清单或运行时配置。

至少记录：源提交／样板版本、所用资源、SDK 与实际后端、视口／DPR、命令及退出结果、实际玩法步骤和断言、截图／动作记录、失败与未验证项目。性能另记固定负载、窗口、计数口径和原始样本。

## 交接模板

完成一个阶段后，用以下结构写入阶段记录并向用户报告：

```text
阶段：M__；样板版本／被测提交：__
原游戏只读基线：__；原游戏／旧兼容／归档保留检查：__
本次实际完成：__
与原版仍有的差距：__
检查与实机结果：命令、通过／失败／未验证、证据路径
当前可试玩入口：__（说明本机或公网，不沿用失效端口）
下一阶段建议：__（未执行）
大白话：这次玩家能看到什么变化，还没做好什么。
```

没有实际运行的项写“未验证”，环境阻塞写具体原因；不要填“应该没问题”。可逆本地修复在当前任务范围内继续做，不把每个技术选择变成审批。
