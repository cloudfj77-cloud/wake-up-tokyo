# 《Wake up 打工人！》天工迁移版 Prompt 工程

Prompt 文档版本：1.0.0。文档基准：原游戏 v0.3.76、天工样板 0.1.0。本工程是一套交给开发 Agent 的任务说明，本次没有执行新的游戏迁移或修改运行代码。

## 怎么用

在能访问本机工程目录的 Codex／天工开发 Agent 中，粘贴下面这段即可：

```text
请在 /Users/cloud/Desktop/Cloud 硬盘/Games for Dev/Wake Up/wake-up-tiangong-sample 中工作。
先读取 AGENTS.md，再读取 prompts/tiangong-migration/PROMPT.md、PHASES.md 和 ACCEPTANCE.md。
按总指令执行第一阶段 M1：还原咖啡店切片的人物贴图和画面风格，接回原角色动作并验证基础动作切换。
保留原游戏和旧兼容工程，只修改独立天工样板。先核对当前状态，然后实现、实测并打开给我试玩。
不要把“导入成功”当作“迁移完成”；给我实际结果、截图和还没做好的地方，最后用大白话总结。
```

这里的 M1 有意只做原有场景切片；墙体碰撞、完整武器反馈和整图迁移在后续阶段。第一阶段完成后保留试玩版本，下一阶段按用户安排继续，不自动扩大成整款游戏改造。

需要改阶段时，把上面“按总指令执行第一阶段 M1”这一行替换为“按阶段文件执行 M2／M3／M4／M5”，同时保留总指令与验收清单。已有相关工作时先验真并复用，避免重复创建工程。

不能读取本机文件的 Agent，需要把下面三个文件的正文一起提供，并准备对应代码、资源和官方 SDK；仅发本机路径无法让远端 Agent 访问它们。

## 文件

- [PROMPT.md](PROMPT.md)：总任务、路径、保留范围、原生技术约束和第一步。
- [PHASES.md](PHASES.md)：每个阶段做什么、怎么验收、何时交付。
- [ACCEPTANCE.md](ACCEPTANCE.md)：玩法核对表、证据要求与交接模板。

## 当前已知起点

独立样板已有真实咖啡店场景、角色网格、简单拾取／射击／感染和跳滚状态切换。原生官方游玩验收通过过，局部静置测试与 Three.js 对照均约 60 帧。这些属于历史证据，不能证明未来改动通过，也不能证明完整游戏已迁移。

人物贴图、角色动作、原版漫画风格、完整碰撞、武器与感染表现、整图系统仍需工作。详细现状见 [迁移报告](../../docs/migration-report.md)。
