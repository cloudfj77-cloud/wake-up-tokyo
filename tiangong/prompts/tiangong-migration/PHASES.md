# 分阶段迁移任务

文档版本 1.0.0。阶段编号是任务顺序，不是游戏版本号，也不代表当前完成状态。M0 是核对，默认开发任务只执行 M1；后续阶段由用户安排。

## M0：核对现状

读取总指令中的基线和证据，记录实际 SDK、项目提交、版本、源资产与本地未提交改动。现有报告是历史结果，不能未经复测照抄为当前通过。确认保留原工程、旧兼容工程及归档。

产出一段现状说明和本阶段清单即可；不创建第二份相同样板，不修改原游戏，不因目前是简化切片而重做整个项目。

## M1：还原人物、动作与画面（默认首个开发任务）

目标：玩家在相同咖啡店切片里，能认出是原游戏的人物、场景和漫画风格，人物不再是没有贴图的静态浅色模型。

1. 在原游戏只读检查 `public/mixamo/manifest.json` 和运行时贴图／动画绑定代码。现有 FBX 本身不带完整贴图，不盲目修改材质常数来冒充修复。
2. 把所需原版贴图、模型及动作复制到样板。当前 manifest 声明了 base_color、normal、roughness、metallic；实际接法、色彩空间、UV／flip 和缩放以源码与原版画面核对。
3. 接入原生蒙皮与动画：待机、移动、跳跃、翻滚、持枪／射击所需片段；动作选片与用户实际输入一致。区分模型导入、关节绑定、动画播放和动作混合，不将任一项单独视作完成。
4. 接回基本切换表现：移动中翻滚、跳接滚、滚接跳。避免双重 root motion、错误脚底高度、人物漂移和无输入卡动作。完整物理和复杂地形在 M2 验证。
5. 使用固定位置、相机、FOV、视口比较原版与原生。按官方原生能力补齐当前切片可实现的漫画描边、颜色、材质和明暗；先查 native equivalent，不擅自把漫画风改成另一种美术风格。
6. 需要恢复原版武器模型用于持枪动作时，一并恢复可辨认的挂接；完整喷射、后坐力和感染表现留在 M3，不为了截图另外摆一把与游戏状态无关的道具枪。

证据：原版／原生同机位对照；待机、移动、跳跃、翻滚、持枪／射击画面或动作片段；真实按键切换与刷新检查；小尺寸 HUD 布局。声音和性能不因画面通过而算通过。

交付：一个人物和基本画面还原后的可试玩切片，列出无法等价实现的效果、明确差异与原因。没有完成的项目保留“未完成”，不能因能力可用就打勾。此时停止扩大范围，交给用户试玩。

## M2：动作手感、碰撞与命中

依赖：M1 的当前角色表现经核对；用户指定继续本阶段。

- 以原版实际速度、视角和操作为准，避免再次对已经减半的速度减半。空格翻滚、Shift 跳跃、E 奔跑；移动中一次按键立即翻滚，射击也能立即切到跳／滚，不增加恢复僵直、额外冷却或必须松开方向键的前置条件；空中动作次数按原版和用户要求核对，不擅自改规则。
- 原生接入楼梯、坡面、墙体、栏杆及房间通路的碰撞；分别检查上楼、下楼、贴墙、转角、空中切换和落地，不用烘焙地面高度冒充完整碰撞。
- 相机不钻墙，不用相机抖动掩盖动作错误；准星和射线坐标正确，屏幕中心点与圆心一致。
- 使用真实射线或弹体命中与遮挡规则：墙后敌人不会被直接命中，友军不会误算敌方感染命中。
- 有效命中三次后蓄满，下一发消耗强化；未命中不计数，避免一次命中回调重复累计，按原版确认强化弹穿透／溅射的计数规则。

证据：动作组合、单次触发、墙后遮挡、楼梯与房间通路、三次命中／第四发强化的正反例。保持正常出生和目标行为，不为测试改敌人位置。

## M3：武器、感染反馈与交互

依赖：命中与阵营转换已可靠；用户指定继续本阶段。

- 注射器恢复肩扛外形，紫色液体可见；每次发射抬枪回弹，奔跑、跳滚与射击切换都不会丢失武器。
- 紫色液体喷射、弹道、命中反馈；地面和墙面留痕在当前场景中持续保留。核对原版上限、存档规则和重载行为，不能沿用样板“最多 64 个”就声称永久留痕完成。
- 玩家亲自感染才触发偏下方的明显紫色圆形主标与“感染成功”；六个尖按个人感染顺序逐个累积，满六循环。感染侧边记录包含正常事件来源，不被大标触发条件吞掉。
- 主标消失时间按原版最新已验收行为复核，避免再次机械减半；声音采用原版感染爆炸反馈，在解锁音频后可清晰听见，检查音量层级、叠加与削波，不用临时合成音冒充还原。
- 敌方红、友方和玩家绿，血条不透明且稳定；感染过程有清晰过渡，结束后模型、阵营、AI、血条一致，不只有 UI 改色。
- 咖啡店固定注射器拾取点，黄色引导光圈、待拾取发光、拾取提示及武器装备状态一致。以原版实际位置和触发方式为准。

证据：玩家亲自感染／友军感染、六次累积与下一轮、阵营过渡、拾取、持枪后坐力、两类表面留痕、声音实际检查；持续发射结束后的特效／音频／资源回收。

## M4：性能和稳定性

依赖：双方画面、角色模型／动画、碰撞和效果负载已经足够一致；仍有差距时先量化，不能以简化版胜过完整版作迁移理由。

1. 固定源提交／资源哈希、SDK、浏览器、实际后端、硬件、Workers、人数、路线、相机、分辨率、DPR、阴影／AA／后处理、输入事件。两边分开运行。
2. 测 12／60／120 个真实等价角色，1280×720 与 1920×1080、DPR 1，分别覆盖静置、移动与转镜、持续射击／感染。保持原样板的 12 人轻负载结果，不能替换后不标明变更。
3. 每组预热至少 5 秒，稳定采样 30 秒并重复 3 次。天工记录实际渲染完成帧；对照记录真实绘制与 GPU 完成证据，写明计数差别。没有足够精确的完成时间戳时不编造 P95／GPU 帧时。
4. 同为约 60 帧可能只是刷新率／调度上限，不计算“领先百分比”；CPU update、启动时间、截图生成耗时不能拿来代替整帧表现。
5. 再做至少 10 分钟持续游玩与停止输入后的观察，记录卡顿、资源／内存、粒子、留痕与音频回收。刷新和重复进入也要覆盖。
6. 不能取得硬件后端或稳定测量时，记录未验证和原因；软件截图不能当作硬件性能结果。

交付：配对设置、原始采样、实际截图、结果表和结论。结论只能是证据支持的“有收益／未见收益／当前还不可比”，不能预设必须迁移。

## M5：扩展为完整原生迁移版

依赖：用户决定继续；逐个子项实现和试玩，不一口气改完所有系统。

推荐顺序：完整海滨地图及默认入口 → 东京和地铁区域 → 双侧列车在站内持续运行／离开可停止 → 真实 NPC 与 AI／敌友关系 → 武器和技能 → 升级卡片／HUD → 警戒、任务和 Boss → 剧情、暂停与设置 → 存档 → 手机操作。

卡片点击直接获得能力；刷新仅目标卡动；能力按获得顺序连续排列；Boss 登场与结束字恢复原版实心可读效果；剧情跳过保留用户最后确认的行为。其余数值和界面以原版最新明确要求核对，不按旧聊天片段重复“修复”。

每项验证用户完整路径，不以 debug 按钮直接跳到结果作为唯一证据。最终检查两张地图、默认海滨、正常开局到结束、保存／重载及手机触控。

这阶段仍在独立工程内完成；替换主项目、合并 PR、发布和生成平台安装包不包含在默认范围，按用户实际要求另行执行。旧兼容工程和归档继续保留。
