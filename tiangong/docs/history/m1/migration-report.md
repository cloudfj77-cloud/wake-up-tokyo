# v0.3.76 → 天工原生迁移试验报告

日期：2026-11-06；样板独立版本 0.1.0。

## 结论

**迁移路线能跑通，暂时不切换正式游戏。** 真实咖啡店场景、原角色网格、输入与基础感染玩法已在天工原生 WebGPU/ECS 中跑起来。相同规模测试里两边都约 60 帧，未观察到能支持迁移决策的性能优势。人物材质、动作和原版漫画画面尚未对齐，不能把本次结果称为完整游戏迁移成功。

## 实际接入了什么

- 原生 Engine 根与 Frontend 根插件；状态由 World 资源持有，Update 系统推进，GUID 资源实例化到 ECS，DOM/声音仅在 Frontend。
- 从东京地图提取地铁出口面向咖啡店的一段实景：1866 个节点、216 个网格、70 个材质、25 张图片，约 11.8 MB。原场景 82.7 MB 未改。原 FBX 角色网格也实际导入。
- WASD 移动、E 奔跑、Shift 跳跃、空格翻滚；动作的新按键可立即打断当前跳滚；地面来自原地图烘焙导航数据。
- 黄色拾取标记、三次命中蓄满后的下一发强化、感染后测试巡警从红转绿、基础紫色弹丸/地面留痕、HUD 与合成感染提示音。

原生运行代码没有 Three.js 或 iframe。Three.js 只存在于独立 reference 对照页及离线资源提取工具。官方验收确认 WebGPU 硬件后端、Engine/Render/Kernels Worker 开启；本场景没有符合派发条件的 kernel，**未使用 shared kernel 加速**。

## 实机验收

官方 `project play`：**8 个步骤通过**，包括真实按键移动拾取、三次命中感染、下一发强化、移动翻滚、跳跃取消翻滚、翻滚取消跳跃；脚本还断言刷新后能重新进入且发射数重置。3 项规则测试、类型检查、项目检查、资源检查及两边的正式构建通过。正式原生构建 131 个产物、约 28.7 MB，另对该构建预览做了进入、拾取、感染和刷新检查。无浏览器 console/page 错误。截图已人工查看，含感染前后与刷新后。

Three.js 对照：同样完成拾取、感染、两次翻滚/一次跳跃及刷新测试，无 page 错误。两边均使用同一 GLB/FBX、规则、相机、HUD、12 个代理巡警、无阴影/无抗锯齿、PBR + ACES。视口均为 1280×720，DPR 1，Chrome 157.0.8103.38，Apple M4 Pro（Metal）。

## 性能窗口

分开运行窗口，预热 5 秒，固定初始相机、无按键输入，测量约 10 秒，避免两窗口同时争抢 GPU。窗口测的是稳定静置，不是持续射击或整图压力测试。

| 项目 | 天工原生 | Three.js 对照 |
|---|---:|---:|
| 采样时长 | 10.000 秒 | 10.002 秒 |
| 完成/提交并栅栏确认帧数 | 600 | 601 |
| 对应吞吐 | 60.00 帧/秒 | 60.09 帧/秒 |

天工取 `execution.render.completedFrame` 起止差；全局完成计数略有快照时差（601），未将其冒充精确 GPU 帧时。Three.js 统计实际 render 调用并在窗口两端用 WebGL GPU fence 确认已提交工作完成。两种后端计数口径仍有差别；端点一帧的误差不表示性能领先。

**双方都接近 60Hz 调度上限；本次测不到上限性能，不能由此算加速百分比。** 原生 hostFrameMs/engineUpdateMs 为执行片段，不等于整帧或 GPU 时长，未拿它与 Three.js 帧间隔混比。开发服务器首次编译/资源导入耗时也不算帧率。

## 真实差距与下一步

- 画面：咖啡店贴图和几何已显示，天工整体偏亮，金属/玻璃/透明材质还需校准。角色缺少原游戏在运行时另行绑定的贴图，天工为浅色、Three.js 为暗色；尚未重接角色动画和原版漫画描边。图像不相同，性能结果只能视作探索。
- 玩法：NPC 为代理形状；地面导航仅是简化碰撞，射击未完成墙体遮挡/物理碰撞。未移植 Boss、技能卡、完整 AI、手机操作和列车。
- 反馈：枪械为基础肩部几何，喷射和留痕为基础形状（最多 64 个），声音为临时合成音。没有声称还原原版喷汁、墙面留痕、后坐力和六尖感染标。
- 若继续：先补同一角色贴图/动作与画面标定、碰撞/命中遮挡，再测 60/120 个角色、持续射击和地图移动，增加更高分辨率、内存与长时间稳定性窗口。通过后再讨论整图迁移。

## 导入兼容问题

原场景含重复身份、无名 sampler 和少量超范围顶点颜色；只在两边共用的场景副本里规范化。首次真实启动遇到 `material-artifact-conflict / param-schema`，改为自定义材质继承同一导入材质契约后，官方游玩验收通过。没有改 SDK、生成目录或缓存来绕过。首次失败报告和修复后结果都保留在 evidence，细节见 [问题记录](feedback.md)。
